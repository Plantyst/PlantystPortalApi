Plantyst 401 Unauthorized

Invalid credentials

An API key or HTTP Basic credentials were presented and the API rejected them.

https://apidocs.plantyst.com/errors/invalid-credentials

What it means

The request carried an API key - in the X-API-KEY header, in the api_key query parameter, or as the password of HTTP Basic authentication - and the key was not accepted. The usual causes are:

  • the key is not valid, or it has been revoked;
  • the key has passed the end of its validity period;
  • the key belongs to a user account that is no longer active;
  • with HTTP Basic, the username is not the e-mail address of the user the key belongs to.

Keys are matched exactly, including letter case, so a value that has been re-typed, truncated or trimmed of characters lands here as well. This problem type is about a key or Basic credentials; an access token that is refused reports invalid-token instead.

What to do

  • Treat this as a configuration error - repeating the request will not change the outcome.
  • Verify the key is passed in full and unchanged, and that the account it belongs to is still active. A new key is issued on request at support@plantyst.com.
  • Prefer the X-API-KEY header. The api_key query parameter works, but URLs tend to end up in logs and browser history.

Example response

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="https://portal.plantyst.com"
Content-Type: application/problem+json

{
  "type": "https://apidocs.plantyst.com/errors/invalid-credentials",
  "title": "Invalid credentials",
  "status": 401,
  "detail": "The credentials sent with the request were rejected."
}
