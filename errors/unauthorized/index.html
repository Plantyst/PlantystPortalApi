Plantyst 401 Unauthorized

Unauthorized

The request was not authorized, and the API could not determine a more specific reason for it.

https://apidocs.plantyst.com/errors/unauthorized

What it means

This is the general problem type for a request that was not authorized. The API uses it whenever it cannot attribute the refusal to one specific cause, so it covers several situations:

  • no credentials were sent with the request;
  • the request relied on a Portal session cookie that has expired or is no longer valid;
  • credentials were sent and accepted, but they do not grant access to this resource - for example a device or an integration that is missing one of the rights the endpoint requires.

Because the type is deliberately broad, do not read it as "no credentials were sent". Read it as "not authorized, reason not stated". More specific problem types may be introduced next to this one later; a client that branches on this type keeps working when they are.

What to do

  • Check that credentials are actually being sent - see the Authorization chapter of the reference for the accepted mechanisms.
  • API clients must not rely on a Portal session cookie. Use an API key or an OAuth2 access token instead.
  • When the credentials are correct, verify that the user or integration they belong to has the access right the endpoint requires. The reference states the minimal right for every operation.
  • Do not retry the request unchanged - the outcome will not differ until the credentials or the rights change.

Example response

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="https://portal.plantyst.com"
Content-Type: application/problem+json

{
  "type": "https://apidocs.plantyst.com/errors/unauthorized",
  "title": "Unauthorized",
  "status": 401,
  "detail": "The request was not authorized. Check that valid credentials were sent and that they grant access to this resource."
}
