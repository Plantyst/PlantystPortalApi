Plantyst 400 Bad Request

Invalid request

The Authorization header of the request could not be parsed.

https://apidocs.plantyst.com/errors/invalid-request

What it means

The API could not read the Authorization header at all, so it never got as far as checking any credentials. The header has to be a scheme and a value separated by a single space:

Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1NiJ9...

Malformed headers that end up here include a scheme with no value, a value with no scheme, two authentication schemes in one header, and a header whose value contains a line break - which happens when a token is pasted with a trailing newline.

This is the only authentication problem answered with 400. Credentials that are read but refused are answered with 401 - see invalid-token and invalid-credentials.

What to do

  • Fix the header and repeat the request. Retrying it unchanged will fail the same way.
  • Check for whitespace and line breaks around the token - trim the value before you put it in the header.
  • Let the HTTP library build the header rather than concatenating it by hand.

Example response

HTTP/1.1 400 Bad Request
WWW-Authenticate: Bearer realm="https://portal.plantyst.com", error="invalid_request"
Content-Type: application/problem+json

{
  "type": "https://apidocs.plantyst.com/errors/invalid-request",
  "title": "Invalid request",
  "status": 400,
  "detail": "The Authorization header could not be parsed."
}
